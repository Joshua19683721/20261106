# 小考系統

給四年級兒子用的「短時間練習」：選一科 → 選 20／30／40 題 → 作答 → 交卷 → 爸爸收到通知 → 一起檢討 → 標記已檢討（下次不再抽到）。

## 一次性設定（約 10 分鐘）

1. **建立 Supabase 專案**（免費、不用信用卡）
   - <https://supabase.com/dashboard> → New project
   - Region 選 Singapore 或 Tokyo

2. **建立資料表**
   - SQL Editor → New query → 貼上 [`supabase.sql`](supabase.sql) 全部內容 → Run
   - 已經設定過的人：再執行一次會補上 `retry_questions`（再考清單）與 `questions`（題庫備份），不會動到舊資料。

3. **取得兩個值**
   - Project Settings → API
   - `Project URL`（`https://xxx.supabase.co`）
   - `anon public` key

4. **建立 ntfy 推播頻道**
   - 手機安裝 ntfy App → Subscribe to topic → 輸入頻道名稱
   - 電腦可開 `https://ntfy.sh/你的頻道名稱` 並允許通知
   - 頻道名稱請用隨機英數字，不要用姓名或電話

5. **填回 `config.js`**
   - 開 [`setup.html`](setup.html)，貼上三個值 → 測試 → 複製產生的 `config.js`
   - 到 GitHub 覆蓋 `小考/config.js` → Commit
   - 等 1 分鐘 Pages 重新部署

## 題數

| 範圍 | 數量 |
|---|---|
| 10/19–11/6 六科每日卷 | 6 科 × 19 卷 × 50 題 = **5,700 題**（含跨卷重複） |
| 六科去重後 | **1,868 題** |
| 英語文四年級單字測驗 | 20 個生活場景、**375 題** |
| 小考全部去重後 | **2,243 題** |

- 首頁寫的 5,700 題只算六科每日卷，不含單字測驗。
- 小考頁是 7 科；但單字測驗不是 19 卷 × 50 題，而是 375 題。
- 如果把第 7 科當成 950 題、再加一次 375 題，會得到 7,025 題，這是重複計算。
- 管理頁「題庫總表」顯示的 2,243 題，是全部題目去重後、實際會被抽到的題數。

## 出題規則

- 題庫來源：該科的題庫（段考六科是 19 張試卷；「英語文四年級單字測驗」是 20 個生活場景、375 題），全部攤平後**去重**（同一道題在不同卷重複出現只算一題）。
- 題目 ID 用「題幹 + 選項集合（排序）+ 正確答案 + 短文」算雜湊，所以選項打散不影響 ID。
- 抽題優先序：
  1. 爸爸按「討論過了，放回題庫」的**再考題目**最優先
  2. 排除爸爸標記「已檢討」的題目
  3. 優先抽兒子**沒做過**的題目
  4. 依單元輪流抽，讓一份小考涵蓋多個單元
  5. 真的不夠才回頭抽做過但還沒檢討的題目
- 每題 45 秒（`SECONDS_PER_QUESTION`），時間到自動交卷。
- 選項順序沿用原試卷，不再二次打散。

## 兒子的畫面

- 作答中不顯示對錯。
- 英語文（含「英語文四年級單字測驗」）的題目旁有 🔊 喇叭：
  - 英→中：題幹單字旁有喇叭。
  - 中→英、例句填空：每個英文選項旁都有喇叭，可以聽發音再選。
  - 語音固定 en-US，優先使用 Windows 內建的 **Microsoft Mark**；沒有 Mark 時自動退回其他 en-US 語音。
  - 點喇叭不會選到那個選項。
- 交卷後只顯示「已通知爸爸」，**不顯示分數、答案與詳解**（可用 `SHOW_SCORE_TO_STUDENT: true` 改成顯示分數）。
- 支援手機、鍵盤（A/B/C/D、左右方向鍵）。

## 爸爸的畫面

- 每 20 秒自動輪詢；有新考卷會跳出提示、響聲與瀏覽器通知。
- 每份考卷顯示：分數、正確率、用時、待標記題數。
- 每題顯示：單元／小節、難度、出處卷、短文、題幹、四個選項（標出正解與兒子的選擇）、詳解、以及「兒子選的選項為什麼不對」。
- 三種處理方式：
  - **標記已檢討**：學生已經會了，之後不再抽到。
  - **討論過了，放回題庫**：放進「再考清單」，下次小考**優先**出這題；如果原本已標記檢討，會自動移除標記。兒子下次作答後自動從再考清單移除（沒作答會留著）。
  - **取消標記／取消再考**：把題目放回一般題庫。
- 「已標記題目」頁可查看與取消標記；「再考清單」頁可查看與取消再考。
- **題庫總表**頁：
  - 每一科、每一個單元的「總題數／已測驗／未測驗／已檢討／再考」統計。
  - 資料檢查：找出題庫裡找不到的已檢討／再考 ID、同時出現在兩張表的題目。
  - 可依科目、狀態、題目文字搜尋每一題的狀態。
  - 勾選題目（可「全選目前篩選」或「勾選全部測驗過的」）→「加入再考清單」，下次小考優先出這些題目；已檢討的題目會自動從已檢討清單移除。
  - 「匯入／更新資料庫題庫」會把 `questions.json` 的 2,243 題寫進 Supabase 的 `questions` 表，已存在的同 ID 題目會更新，不影響交卷紀錄。
  - 統計表由 `manifest.json` 產生；題庫更新後執行 `node 小考/tools/build-manifest.js` 重建（同時產生 `questions.json`）。

## 資料表

`submissions`
- 每次交卷一列，`items` 存當下完整題目快照，所以之後題庫改版也看得到舊考卷的內容。

`done_questions`
- 已檢討題目，`id` 是穩定雜湊（主鍵），重複標記不會產生重複列。

`retry_questions`
- 爸爸按「討論過了，放回題庫」的題目，出卷時優先抽。
- 兒子上交卷後，有作答的再考題目會自動刪除；沒作答的留著。

`questions`
- 完整題庫備份（`id`、科目、單元、摘要、`data` 內含題幹／選項／答案／詳解）。
- 由管理頁「匯入／更新資料庫題庫」寫入；小考出題仍讀題庫檔，這張表是備份與管理用。
- 題庫檔更新後，重新按一次匯入就會更新同 ID 的題目。

> 舊資料庫如果只有 `submissions` 和 `done_questions`，重新執行一次 [`supabase.sql`](supabase.sql) 就會補上 `retry_questions` 與 `questions`，不會影響原有資料。

## 常見問題

**Q：Supabase 免費專案會不會睡著？**
會，連續 7 天沒有使用會暫停。到 Supabase 後台按 Restore 即可，資料不會不見。兒子的頁面若讀不到資料會顯示錯誤訊息。

**Q：推播沒收到？**
- 確認 ntfy App 已訂閱同一個頻道名稱（大小寫、減號都要一樣）。
- 到 `setup.html` 按「測試推播」。
- 交卷仍然會寫進資料庫，管理頁照樣看得到，只是少了即時通知。

**Q：想改每題秒數？**
改 `config.js` 的 `SECONDS_PER_QUESTION`（例如 60）。

**Q：想讓兒子看到分數？**
改 `config.js` 的 `SHOW_SCORE_TO_STUDENT: true`。

**Q：題目不夠 20 題？**
代表該科大部分題目都被標記已檢討了。到管理頁「已標記題目」取消一些標記即可。

## 安全性說明

這是家用網站，沒有登入機制：

- Supabase 的 anon key 本來就是公開的，資料表透過 RLS 開放匿名讀寫。
- 也就是說，**知道網址的人可以讀取交卷紀錄、也可以標記題目**。
- 管理頁密碼只是擋一下，不是真正的資安防線。
- ntfy 頻道名稱同樣是「知道就能發訊息」。

若之後要更嚴格，可以改成 Supabase Auth 登入（爸爸一組帳號），並把 RLS 收緊到 `authenticated`。
